# Установка с нуля

Инструкция рассчитана на человека, который умеет арендовать сервер и открыть
терминал. Знать, как устроены WireGuard, REALITY и iptables, не требуется —
всё, что нужно понимать по ходу, объясняется на месте.

Времени займёт около 20 минут, из них большая часть — ожидание.

---

## Что мы собираем

Два сервиса. Их можно ставить вместе, а можно по отдельности.

**Панель** — это VPN-сервер, к которому подключаются ваши устройства. Она
выдаёт клиентам конфиги и QR-коды, показывает, кто онлайн и сколько трафика
прошло.

**Релей** — отдельный сервер-посредник. Нужен, если вы хотите, чтобы сайты
видели не адрес вашего VPN-сервера, а адрес релея. Панель умеет заворачивать
весь трафик клиентов через релей — это называется каскад.

Самый частый сценарий — два сервера в разных странах: панель там, куда удобно
подключаться, релей там, чей адрес должны видеть сайты. Но если каскад вам не
нужен, ставьте только панель и переходите сразу к её разделу.

```
   ваш телефон ──► сервер с панелью ──► (каскад) ──► сервер с релеем ──► интернет
                   принимает клиентов                 его адрес видят сайты
```

---

## Что нужно заранее

- Сервер с Ubuntu или Debian и правами root. Хватит самого дешёвого:
  1 ядро, 1 ГБ памяти, 10 ГБ диска.
- Установленный Docker. Если его нет:

  ```bash
  curl -fsSL https://get.docker.com | sh
  ```

- Для панели дополнительно нужно разрешить серверу пересылать чужие пакеты:

  ```bash
  echo 'net.ipv4.ip_forward=1' >> /etc/sysctl.conf
  sysctl -p
  ```

  Без этой строки клиенты подключатся, но интернета у них не будет.

## Часть 1. Релей

Пропустите эту часть, если каскад вам не нужен.

### Шаг 1. Создать каталог и файлы

```bash
mkdir -p /opt/noisefloor-relay && cd /opt/noisefloor-relay

cat > docker-compose.yml << 'EOF'
services:
  relay:
    image: vbif666/noisefloor-vless-reality:latest
    container_name: NOISEFLOOR-vless-reality
    restart: unless-stopped
    network_mode: host
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
    environment:
      VLESS_PORT: "${VLESS_PORT:-8443}"
      PANEL_PORT: "${PANEL_PORT:-8001}"
      REALITY_DEST: "${REALITY_DEST:-dl.google.com:443}"
      PUBLIC_HOST: "${PUBLIC_HOST:-}"
      LABEL: "${LABEL:-relay}"
      ADMIN_USERNAME: "${ADMIN_USERNAME:-admin}"
      ADMIN_PASSWORD: "${ADMIN_PASSWORD:-}"
      APP_CODENAME: "${APP_CODENAME:-Relay-01}"
    volumes:
      - ./data:/data
EOF

cat > .env << 'EOF'
# Публичный адрес этого сервера. Впишите свой IP или домен.
PUBLIC_HOST=
# Как этот сервер будет называться в списке серверов клиентского приложения.
LABEL=my-relay
EOF
```

Впишите в `.env` адрес сервера. Узнать его, если не помните:

```bash
curl -s https://ifconfig.me
```

### Шаг 2. Запустить

```bash
docker compose pull
docker compose up -d
```

### Шаг 3. Забрать пароль

Пароль администратора генерируется сам при первом запуске:

```bash
docker exec NOISEFLOOR-vless-reality cat /data/INITIAL_ADMIN_PASSWORD.txt
```

Сохраните его. Панель релея откроется по адресу `http://ВАШ_АДРЕС:8001`,
логин `admin`, пароль — из команды выше. На странице будет **токен
синхронизации** — он понадобится в части 3.

Ссылки подключения и QR-кода там нет намеренно: в ссылке лежит UUID, то есть
готовый доступ к релею, а для связки серверов достаточно токена. Если релей
нужен вам как самостоятельный эндпоинт для обычного клиентского приложения,
ссылку можно забрать через API:

```bash
curl -s -u admin:ПАРОЛЬ http://127.0.0.1:8001/api/status \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["vless_url"])'
```

### Шаг 4. Убедиться, что всё работает

```bash
docker ps
```

Напротив контейнера должно быть `Up` и `(healthy)`. Если вместо этого
`Restarting` — смотрите, что пошло не так:

```bash
docker logs NOISEFLOOR-vless-reality --tail 30
```

## Часть 2. Панель

### Шаг 1. Создать каталог и файлы

```bash
mkdir -p /opt/noisefloor-panel && cd /opt/noisefloor-panel

cat > docker-compose.yml << 'EOF'
services:
  panel:
    image: vbif666/noisefloor-amneziawg-panel:latest
    container_name: NOISEFLOOR-amneziawg-panel
    restart: unless-stopped
    network_mode: host
    cap_add:
      - NET_ADMIN
    devices:
      - /dev/net/tun
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
    env_file:
      - .env
    volumes:
      - ./data:/opt/panel/data
      - ./awg_config:/etc/amnezia/amneziawg
EOF

cat > .env << 'EOF'
ADMIN_USERNAME=admin
ADMIN_PASSWORD=
SECRET_KEY=
AWG_INTERFACE=awg0
EGRESS_INTERFACE=auto
LIVE_MANAGEMENT_ENABLED=true
AUTO_APPLY_ON_START=true
DEFAULT_SERVER_ADDRESS=10.13.13.1/24
DEFAULT_LISTEN_PORT=443
DEFAULT_DNS=1.1.1.1
# Пароль для шифрования резервных копий. Оставите пустым — копии будут
# лежать незашифрованными, а внутри них ключи всех ваших клиентов.
BACKUP_PASSPHRASE=
EOF
```

Пустые `ADMIN_PASSWORD` и `SECRET_KEY` — это нормально: они сгенерируются сами.

### Шаг 2. Запустить

```bash
docker compose pull
docker compose up -d
```

### Шаг 3. Забрать пароль и войти

```bash
docker exec NOISEFLOOR-amneziawg-panel cat /opt/panel/data/INITIAL_ADMIN_PASSWORD.txt
```

Откройте `http://ВАШ_АДРЕС:8000` и войдите. В правом верхнем углу должно быть
зелёным написано «awg0 активен» — значит VPN-сервер поднялся.

### Шаг 4. Указать адрес сервера

Вкладка **Сервер** → поле «Публичный адрес сервера» → впишите IP или домен
этого сервера → **Сохранить** → **Применить на сервере**.

Это тот адрес, на который будут подключаться ваши устройства. Если его не
указать, в конфигах клиентов окажется заглушка и они не подключатся.

### Шаг 5. Добавить первое устройство

Вкладка **Пиры** → **+ Добавить пира** → введите имя (например, «Телефон») →
**Создать**.

Откроется окно с QR-кодом. Установите на телефон приложение **AmneziaWG**
(есть в App Store и Google Play), нажмите в нём «+», выберите сканирование
QR-кода и наведите камеру на экран. Для компьютера удобнее кнопка
**Скачать .conf** — получившийся файл импортируется в то же приложение.

Подключитесь. В панели напротив устройства загорится зелёная точка, а в
разделе «Трафик» пойдёт график.

## Часть 3. Связать панель с релеем (каскад)

Только если вы ставили релей.

Панель сама забирает параметры у релея и следит за ними дальше — вводить
ничего, кроме адреса и токена, не нужно.

1. Откройте панель релея (`http://АДРЕС_РЕЛЕЯ:8001`) и скопируйте
   **токен синхронизации**.
2. В панели: вкладка **Сервер** → блок **Каскад** → галочка
   «Включить каскад» → впишите адрес релея (`http://АДРЕС_РЕЛЕЯ:8001`) и
   токен → **Синхронизировать сейчас**.
3. Рядом появится «параметры получены только что», а ниже — сводка вида
   `203.0.113.10:8443 · sni dl.google.com`. Дальше панель перепроверяет релей
   каждые пять минут и подхватывает изменения сама.
4. **Сохранить** → **Применить на сервере**.

Параметры подключения хранятся на сервере и в интерфейсе не показываются:
в них входит UUID, то есть готовый доступ к релею. Менять их нужно на самом
релее — панель подтянет изменение.
Дальше в обоих случаях: перейдите на вкладку **Пиры**. Под графиком трафика
появится значок каскада. Как только через него реально пойдут данные, он станет зелёным и
   начнёт пульсировать, показывая скорость.

Проверить, что адрес сменился: на подключённом к VPN устройстве откройте
любой сайт, показывающий ваш IP. Должен отображаться адрес **релея**, а не
панели.

Жёлтый значок вместо зелёного означает, что каскад включён, но данные через
него пока не идут — либо вы ничего не открывали, либо что-то не так; смотрите
раздел «Если что-то пошло не так».

## Что важно сделать после установки

### Закройте панель от посторонних

**Панель управления открыта всему интернету и работает без шифрования.** Любой,
кто знает адрес вашего сервера, видит форму входа, а пароль при входе идёт по
сети открытым текстом.

Самое простое решение — закрыть порты панели фаерволом и заходить в неё через
SSH-туннель:

```bash
# на сервере: разрешаем только SSH и сам VPN
ufw allow 22/tcp
ufw allow 443/udp        # порт VPN на сервере с панелью
ufw allow 8443/tcp       # порт VLESS на сервере с релеем
ufw --force enable
```

После этого панель снаружи недоступна. Чтобы в неё зайти, с домашнего
компьютера:

```bash
ssh -L 8000:127.0.0.1:8000 root@АДРЕС_СЕРВЕРА
```

и откройте в браузере `http://127.0.0.1:8000`. Пока окно с SSH открыто —
панель работает, и никто снаружи её не видит.

### Сохраните резервную копию

В панели: вкладка **Сервер** → **Скачать копию**. В архиве ключи сервера и всех
устройств. Без него потеря сервера означает, что все устройства придётся
настраивать заново.

Копии снимаются автоматически раз в сутки и хранятся на самом сервере, но это
не спасёт от потери сервера целиком — храните хотя бы одну копию у себя.

Если задали `BACKUP_PASSPHRASE`, архив зашифрован; распаковать его можно так:

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -in копия.tar.gz.enc -out копия.tar.gz
tar xzf копия.tar.gz
```

## Если что-то пошло не так

### Клиент подключается, но интернета нет

Скорее всего не включена пересылка пакетов:

```bash
sysctl net.ipv4.ip_forward
```

Должно быть `= 1`. Если `0` — вернитесь к разделу «Что нужно заранее».

### Каскад включён, но значок остаётся жёлтым

Спросите у панели, что она сама об этом думает:

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:8000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"ВАШ_ПАРОЛЬ"}' | python3 -c 'import json,sys; print(json.load(sys.stdin)["access_token"])')

curl -s http://127.0.0.1:8000/api/server/cascade/status -H "Authorization: Bearer $TOKEN"
```

В ответе смотрите на `verified_ok` — панель регулярно сама делает пробный
запрос через каскад:

- `true` — каскад работает, данные проходят;
- `false` — не работает, а в `verify_error` написано почему;
- `-1` или `null` — проверки ещё не было, подождите минуту.

### Не меняйте camouflage-домен на `www.microsoft.com`

Это единственная настройка, которая выглядит безобидно, а ломает всё.
У части серверов Microsoft сертификат оказывается слишком большим, и
библиотека REALITY молча отбрасывает такие подключения. Внешне выглядит
идеально: сервис запущен, ошибок нет, а данные не идут.

Значение по умолчанию `dl.google.com:443` проверено и работает. Менять его
без причины не нужно.

## Обновление

```bash
cd /opt/noisefloor-panel   # или /opt/noisefloor-relay
docker compose pull
docker compose up -d
```

Настройки, ключи и клиенты лежат в каталоге `data` рядом и при обновлении не
теряются. Версии VPN-движка зашиты в образ намеренно: сервер ничего не
докачивает и не пересобирает сам по себе, поэтому обновление происходит тогда,
когда вы его запустили, а не ночью без предупреждения.
