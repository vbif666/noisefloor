# Как вносить изменения

Проект держит в руках чужой трафик и ключи, поэтому здесь чуть строже, чем
обычно принято: любая правка, касающаяся сети, должна быть проверена реально
прошедшим трафиком, а не тем, что сервис ответил `200 OK`.

---

## Окружение

Нужен только Docker. Ни Python, ни Go, ни зависимости локально ставить не
надо — всё гоняется в образах.

```bash
git clone https://github.com/vbif666/noisefloor.git
cd noisefloor

docker build -t noisefloor-panel:dev amneziawg-panel
docker build -t noisefloor-relay:dev vless-reality
```

Сборка панели компилирует amneziawg-go и amneziawg-tools из исходников —
первый раз занимает пару минут, дальше берётся из кэша.

## Тесты

### Юнит-тесты

Стандартный `unittest`, без pytest и вообще без сторонних библиотек: так они
запускаются прямо в рабочем образе и не требуют отдельного окружения.

```bash
docker run --rm \
    -v "$PWD/amneziawg-panel/src:/src" -v "$PWD/tests/unit:/tests:ro" \
    -e PYTHONPATH=/src -w /src noisefloor-panel:dev \
    python3 -m unittest discover -s /tests -p 'test_*.py' -v
```

### Приёмочный тест

Разворачивает оба сервиса с нуля на портах `291xx` и проверяет, что через них
проходит настоящий трафик. Безопасен на машине, где эти же сервисы уже
работают в бою.

```bash
PANEL_IMAGE=noisefloor-panel:dev RELAY_IMAGE=noisefloor-relay:dev tests/smoke.sh

tests/smoke.sh --relay-only     # только релей
tests/smoke.sh --panel-only     # панель и правила фаервола
tests/smoke.sh --rules-only     # только правила
```

Проверка правил гоняется в контейнере с собственным сетевым стеком, поэтому
таблицы хоста не затрагиваются.

### Что обязательно покрывать тестом

- **Любой исправленный баг.** Сначала тест, который падает на текущем коде,
  потом исправление. Тест, написанный после и сразу зелёный, ничего не
  доказывает — проверьте его, временно вернув баг.
- **Инварианты, которые не видны глазами при чтении диффа.** На чём проект уже
  обжигался: адрес, который слушает вход каскада; симметрия правил
  фаервола; непересечение значений `H1-H4`; то, что резервная копия не тянет
  внутрь саму себя.

## Ветки и коммиты

Ветки: `feat/`, `fix/`, `docs/`, `refactor/`, `chore/` плюс короткое описание —
`fix/cascade-udp-leak`.

Коммит: заголовок в повелительном наклонении до 72 символов, пустая строка,
дальше **почему**. Что изменилось, видно из диффа; ценно то, из какой проблемы
изменение выросло и что будет, если сделать наоборот.

```
Перехват через TPROXY вместо REDIRECT

REDIRECT умеет только TCP — у него нет аналога для UDP. Пока перехват был
на нём, весь QUIC и все DNS-запросы уходили мимо каскада напрямую, с
настоящим адресом сервера, хотя каскад выглядел включённым и исправным.
```

## Чек-лист перед PR

- [ ] Юнит-тесты зелёные
- [ ] `tests/smoke.sh` зелёный, если трогали сеть, правила, каскад или сборку
- [ ] Новое поведение закрыто тестом; для багфикса тест проверен падением
- [ ] Обновлён `.env.example`, если появились или исчезли переменные
- [ ] Обновлена документация, если изменились настройки или порядок установки
- [ ] Комментарии в коде объясняют «почему», а не пересказывают код
- [ ] Нет боевых значений: UUID, ключей, адресов серверов

## Никогда не коммитьте боевые значения

Это уже случалось: в тестах оказались настоящий UUID клиента (по сути ключ
доступа к релею), его REALITY-ключ и адреса обоих серверов. Вычищать пришлось
переписыванием всей истории.

Для примеров есть специально зарезервированные диапазоны, и в тестах нужно
использовать именно их:

| Что | Брать |
|---|---|
| IP-адреса | `203.0.113.0/24`, `198.51.100.0/24`, `192.0.2.0/24` (RFC 5737) |
| Домены | `example.com`, `example.org` (RFC 2606) |
| UUID | `00000000-0000-4000-8000-0000000000ff` |
| Ключи и пароли | Строки вида `EXAMPLEkey…`, по которым сразу видно, что это заглушка |

`.env` и каталоги `data/`, `awg_config/` закрыты `.gitignore`. Проверить себя
перед пушем:

```bash
git diff --cached | grep -nE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+|PrivateKey|_pat_|ghp_'
```

## Работа с боевыми серверами

Если правка выкатывается на живой сервер:

1. **Сначала на тестовом развёртывании.** `tests/smoke.sh` поднимает
   изолированную копию — она не мешает боевой на той же машине.
2. **Держите путь отката.** У режима перехвата он есть:
   `CASCADE_INTERCEPT_MODE=redirect`. Если у вашей правки его нет — придумайте,
   прежде чем выкатывать.
3. **Проверяйте трафиком, а не статусом.** `verified_ok` в
   `/api/server/cascade/status` — это результат настоящего запроса через
   каскад. `running: true` не значит ничего.
4. **Помните про клиентов.** Перезапуск интерфейса рвёт все соединения. Это
   секунды, но выбирать момент стоит.

## Стиль

**Python.** Стандартная библиотека предпочтительнее новой зависимости: каждая
из них попадает в образ, который работает от root с `NET_ADMIN`. Строки на 100
символов. Типы в сигнатурах приветствуются.

**Фронтенд.** Три файла без сборщика — так и оставим. Ни npm, ни бандлера,
ни фреймворка: интерфейс здесь простой, а цена инструментальной обвязки выше
пользы.

**Комментарии.** Пишите их там, где решение выглядит странным, и объясняйте
причину. «Слушаем 0.0.0.0, потому что REDIRECT переписывает адрес назначения
на адрес входящего интерфейса, а не на loopback» — полезно. «Открываем сокет» —
нет.

**Сообщения пользователю.** Ошибка должна говорить, что делать. Не «не удалось
обновить», а «этот образ не собирает бинарники на лету — обновитесь через
`docker compose pull`».
