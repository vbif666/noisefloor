# NOISEFLOOR

Самостоятельный VPN на AmneziaWG с возможностью выпускать трафик через второй
сервер по VLESS+REALITY — и разделять маршруты, отправляя часть трафика
напрямую, мимо этого второго сервера.

Два сервиса, каждый разворачивается одной командой и дальше живёт сам:
генерирует ключи, поднимает интерфейс, следит за собственным здоровьем и
делает резервные копии.

```bash
docker compose pull && docker compose up -d
```

**Установка с нуля — [`docs/DEPLOY.md`](docs/DEPLOY.md).** Пошагово, без
предварительных знаний про WireGuard, REALITY и iptables.

## Зачем это

Обычный self-hosted WireGuard решает задачу «получить другой IP», но оставляет
две проблемы.

Первая — трафик WireGuard узнаётся системами фильтрации по характерному виду
пакетов, независимо от того, что внутри. Вторая — сайты видят адрес именно
вашего сервера, а он один, и заблокировать его целиком несложно.

**AmneziaWG** закрывает первую: подмешивает мусорные пакеты и подменяет
заголовки, из-за чего трафик перестаёт выглядеть как VPN. Профиль обфускации
общий для сервера и всех клиентов — панель раздаёт его в конфигах сама.

**Каскад** закрывает вторую: трафик клиентов дополнительно заворачивается через
второй сервер по VLESS+REALITY, и наружу выходит уже его адрес. REALITY
маскирует это соединение под обычный визит на настоящий чужой сайт,
переиспользуя его TLS-сертификат, — со стороны видно неотличимое от обычного
HTTPS.

## Что умеет

- Клиенты добавляются в один клик: ключи, адрес в туннеле и QR-код панель
  генерирует сама
- Обфускация AmneziaWG 2.0 с автоматической раздачей профиля клиентам
- Каскад через второй сервер, в основном режиме покрывающий **и TCP, и UDP**
  (то есть QUIC и DNS тоже, а не только веб)
- Разделение маршрутов: российские адреса можно выпускать напрямую, мимо
  каскада, — они открываются в два-три раза быстрее, а те, что не пускают
  зарубежные адреса, наконец работают
- График скорости по туннелю и живой индикатор того, что каскад реально
  пропускает данные
- Метрики в формате Prometheus для внешнего мониторинга
- Резервные копии по расписанию, с шифрованием
- Автоматическое восстановление каскада после падения
- Клиенты изолированы друг от друга по умолчанию
- Панель синхронизирует параметры каскада с релеем сама — маскировку не нужно
  держать одинаковой на двух серверах вручную
- Ротация маскировки: релей раз в несколько часов (по умолчанию четыре) меняет
  SNI и камуфляжный сайт на случайный из пула, предварительно проверив его с
  себя — TLS 1.3, h2, цепочка сертификатов короче лимита REALITY. Смена
  объявляется заранее, и панель подхватывает её через секунды, а не на
  очередном опросе
- Параметры подключения к релею не выводятся на экран: в них входит UUID, то
  есть готовый доступ к нему, а для связки узлов достаточно токена

## Как устроено

```
   устройство ──► сервер с панелью ──► (каскад) ──► сервер с релеем ──► интернет
                  принимает клиентов                 его адрес видят сайты
                         │
                         └──── (разделение маршрутов) ────────────────► интернет
                               российские адреса, минуя релей
```

| Сервис | Образ | Роль |
|---|---|---|
| **Панель AmneziaWG** | `vbif666/noisefloor-amneziawg-panel` | VPN-сервер: клиенты, обфускация, графики, каскад |
| **VLESS-REALITY релей** | `vbif666/noisefloor-vless-reality` | Выходной узел, за которым прячется панель |

Сервисы независимы. Нужен только VPN — ставьте панель. Нужен только выходной
узел (например, как эндпоинт для стороннего клиента) — ставьте релей.

Подробности и обоснование решений — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Требования

**Сервер:** Linux с ядром 5.6+ (Ubuntu 22.04+, Debian 12+), root-доступ.
Достаточно 1 ядра, 1 ГБ памяти и 10 ГБ диска — оба сервиса вместе занимают
меньше 800 МБ.

Для каскада в режиме по умолчанию (`tproxy`) нужно ядро **6.x или новее**: на
5.15 xray не может выставить `IP_TRANSPARENT` на TCP-слушателе, и ядро молча
отбрасывает весь TCP клиентов. Панель это распознаёт и пишет в ошибку каскада,
а обойтись без обновления ядра можно переключением
`CASCADE_INTERCEPT_MODE=redirect` (тогда TCP пойдёт через каскад, а UDP —
напрямую; QUIC клиентам при этом закрывают, чтобы браузер не уводил основную
часть трафика мимо каскада, — см. `CASCADE_BLOCK_QUIC`). Подробности — в
[`docs/OPERATIONS.md`](docs/OPERATIONS.md).

**Docker** с плагином Compose:

```bash
curl -fsSL https://get.docker.com | sh
```

**Для панели дополнительно:**

- включённая пересылка пакетов — `net.ipv4.ip_forward=1` (без неё клиенты
  подключатся, но интернета не получат). Установщик кладёт её вместе с
  остальной настройкой сети ядра в `/etc/sysctl.d/99-noisefloor.conf`:
  bbr вместо cubic (дальнее плечо каскада иначе теряет до трети полосы),
  буферы сокетов и размер таблицы conntrack (её умолчание на гигабайте
  памяти — около 7 тысяч записей, и десяток активных клиентов их выбирает);
- `NET_ADMIN` и `/dev/net/tun` у контейнера (прописаны в compose);
- `network_mode: host` — интерфейс создаётся в сетевом стеке хоста;
- свободный UDP-порт для приёма клиентов (по умолчанию 443).

**Для каскада** дополнительно нужен модуль `xt_TPROXY` — он есть в стандартных
ядрах Ubuntu и Debian. Проверить: `modprobe xt_TPROXY && echo ok`.

**Для релея:** свободный TCP-порт для VLESS (по умолчанию 8443). Порт 443
обычно занят, и это нормально.

## Быстрый старт

Если ставите на чистый сервер, всю работу сделают два скрипта — по одному на
узел связки. Они ставят Docker, готовят систему, поднимают контейнер и
показывают пароль администратора.

**Сервер 1 — панель.** Точка входа: к ней подключаются устройства. Нужна
всегда, каскад ей не обязателен.

```bash
curl -fsSLO https://raw.githubusercontent.com/vbif666/noisefloor/master/amneziawg-panel/install.sh
bash install.sh
```

Этого уже хватает для работающего VPN. Дальше — только если нужен каскад.

**Сервер 2 — релей.** Выходной узел: его адресом клиенты видны в интернете.

```bash
curl -fsSLO https://raw.githubusercontent.com/vbif666/noisefloor/master/vless-reality/install.sh
bash install.sh --label "Амстердам"
```

В конце он напечатает токен синхронизации. Остаётся связать узлы — вернуться
на сервер 1 и запустить тот же скрипт ещё раз, теперь с адресом релея:

```bash
bash install.sh --relay http://АДРЕС_СЕРВЕРА_2:8001 --relay-token ТОКЕН
```

Повторный запуск безопасен: он обновляет установку, а не сносит её. То же
самое можно сделать мышью — в панели, вкладка «Сервер», блок «Каскад». Что и
почему делает каждый шаг — в [`docs/DEPLOY.md`](docs/DEPLOY.md).

Вручную то же самое выглядит так. Минимальный вариант — только VPN, без
каскада:

Возьмите из репозитория два файла — `amneziawg-panel/docker-compose.yml` и
`amneziawg-panel/.env.example` — и положите их в отдельный каталог на сервере
(второй под именем `.env`). Готовые блоки для копирования, если репозитория
под рукой нет, есть в [`docs/DEPLOY.md`](docs/DEPLOY.md).

```bash
mkdir -p /opt/noisefloor-panel && cd /opt/noisefloor-panel
# сюда положить docker-compose.yml и .env

sysctl -w net.ipv4.ip_forward=1
docker compose pull && docker compose up -d

# пароль администратора генерируется сам при первом запуске
docker exec NOISEFLOOR-amneziawg-panel cat /opt/panel/data/INITIAL_ADMIN_PASSWORD.txt
```

Панель откроется на `http://АДРЕС_СЕРВЕРА:8000`. Дальше: вкладка **Сервер** →
указать публичный адрес → **Применить**, затем вкладка **Пиры** → добавить
устройство и отсканировать QR-код приложением AmneziaWG.

> **Важно.** По умолчанию панель доступна из интернета и работает по обычному
> HTTP без шифрования. Прежде чем оставлять её так, прочитайте в
> [`docs/DEPLOY.md`](docs/DEPLOY.md) раздел «Что важно сделать после
> установки» — там про фаервол и доступ через SSH-туннель.

Полная установка обоих сервисов со связкой в каскад — [`docs/DEPLOY.md`](docs/DEPLOY.md).

## Настройки

Всё задаётся через `.env` рядом с `docker-compose.yml`. Пустые значения там,
где написано «генерируется» — это нормально: сервис заполнит их сам при первом
запуске и сохранит в каталоге данных.

### Панель

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ADMIN_USERNAME` | `admin` | Логин в панель |
| `ADMIN_PASSWORD` | генерируется | Пароль; попадёт в `data/INITIAL_ADMIN_PASSWORD.txt` |
| `SECRET_KEY` | генерируется | Подпись сессий; сохраняется в `data/secret_key` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `720` | Сколько живёт сессия в браузере |
| `AWG_INTERFACE` | `awg0` | Имя сетевого интерфейса туннеля |
| `AWG_CONFIG_DIR` | `/etc/amnezia/amneziawg` | Где лежит конфиг интерфейса |
| `EGRESS_INTERFACE` | `auto` | Внешняя сетевая карта для NAT; `auto` определит сама |
| `LIVE_MANAGEMENT_ENABLED` | `true` | Разрешить панели поднимать интерфейс. `false` — режим генератора конфигов |
| `AUTO_APPLY_ON_START` | `true` | Поднимать туннель при старте контейнера |
| `DEFAULT_SERVER_ADDRESS` | `10.13.13.1/24` | Подсеть туннеля; применяется один раз при первой настройке |
| `DEFAULT_LISTEN_PORT` | `443` | UDP-порт приёма клиентов |
| `DEFAULT_DNS` | `1.1.1.1` | DNS, который получают клиенты |
| `CASCADE_INTERCEPT_MODE` | `tproxy` | `tproxy` — TCP и UDP через каскад; `redirect` — только TCP (откат) |
| `CASCADE_BLOCK_QUIC` | `true` | В режиме `redirect` закрывать клиентам QUIC (UDP/443): иначе браузер уводит основную часть трафика мимо каскада и с другим IP |
| `CASCADE_DNS_VIA_CASCADE` | `false` | В режиме `redirect` заворачивать DNS клиентов в каскад (запрос уходит по TCP через релей) |
| `ISOLATE_CLIENTS` | `true` | Клиенты не видят друг друга внутри туннеля. `false` — если ходите между своими машинами через тот же туннель |
| `BACKUP_PASSPHRASE` | пусто | Задан — резервные копии шифруются AES-256 |
| `AWG_UPDATE_GITHUB_PAT` | пусто | Необязательный токен: поднимает лимит запросов при проверке версий |

**Не всё живёт в `.env`.** Часть настроек меняется на работающей системе и
хранится в базе панели — в файле окружения их нет:

- **ссылка каскада и связка с релеем** (адрес релея и токен синхронизации) —
  вкладка «Сервер», блок «Каскад»; установщик умеет задать их сразу,
  ключами `--relay` и `--relay-token`;
- **разделение маршрутов** («российские адреса — напрямую») — там же, галочкой;
- адрес туннеля, порт, MTU, DNS и профиль обфускации: значения из `DEFAULT_*`
  применяются один раз при первой настройке, дальше правятся в панели.

База `geoip.dat`, по которой работает разделение, лежит в образе, и её версия
закреплена в `Dockerfile` (`GEOIP_REF`) — как и версии всех остальных
сторонних компонентов.

### Релей

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PUBLIC_HOST` | автоопределение | Адрес в ссылке для клиента. **Задайте явно:** иначе сервис ходит определять его наружу при каждом запросе |
| `LABEL` | `vless-reality` | Имя сервера в списке клиентского приложения |
| `VLESS_PORT` | `8443` | TCP-порт VLESS |
| `PANEL_PORT` | `8001` | HTTP-порт страницы статуса |
| `REALITY_DEST` | `dl.google.com:443` | Камуфляжный сайт на старте. **Не меняйте на `www.microsoft.com`** — см. ниже |
| `REALITY_SNI` | из `REALITY_DEST` | Домен, под который маскируемся, на старте |
| `ADMIN_USERNAME` | `admin` | Логин на страницу статуса (Basic-авторизация) |
| `ADMIN_PASSWORD` | генерируется | Пароль; попадёт в `data/INITIAL_ADMIN_PASSWORD.txt` |
| `APP_NAME`, `APP_CODENAME` | `NOISEFLOOR`, `Relay-01` | Косметика заголовка страницы |

> **Ловушка, стоившая нескольких дней.** Часть серверов `www.microsoft.com`
> отдаёт TLS-сертификат больше, чем принимает библиотека REALITY, и она молча
> отбрасывает **каждое** подключение. Снаружи всё выглядит здоровым: сервис
> запущен, ошибок нет, трафика нет. Апстрим-баг
> [XTLS/Xray-core#6356](https://github.com/XTLS/Xray-core/issues/6356).
> Значение по умолчанию проверено и работает.

**Ротация маскировки** настраивается не переменными, а на странице релея —
блок «Ротация маскировки»: галочка, интервал в часах, пул хостов по одному в
строке. Следующий хост выбирается случайно из пула и объявляется заранее;
перед сменой он проверяется с самого релея (TLS 1.3, h2, цепочка сертификатов
короче лимита REALITY — та самая проверка, что отсекла бы `www.microsoft.com`),
непригодный пропускается. Кнопки «Сменить сейчас» и «Проверить пул», журнал
смен. Пул по умолчанию — десять проверенных хостов (`dl.google.com`,
`gateway.icloud.com`, `www.samsung.com`, `www.amd.com`, `www.cloudflare.com`,
`www.mozilla.org`, `www.speedtest.net`, `www.dell.com`, `www.lenovo.com`,
`www.asus.com`). Прежний SNI принимается ещё 15 минут после смены, поэтому
каскад с первого сервера не рвётся ни по расписанию, ни по кнопке.
Подробности — в [`docs/OPERATIONS.md`](docs/OPERATIONS.md).

## Разработка

Ничего, кроме Docker, ставить не нужно: юнит-тесты гоняются прямо в рабочем
образе, приёмочные поднимают сервисы на изолированных портах и не мешают уже
работающим на этой же машине.

```bash
# собрать образы
docker build -t noisefloor-panel:dev amneziawg-panel
docker build -t noisefloor-relay:dev vless-reality

# юнит-тесты
docker run --rm \
    -v "$PWD/amneziawg-panel/src:/src" -v "$PWD/tests/unit:/tests:ro" \
    -e PYTHONPATH=/src -w /src noisefloor-panel:dev \
    python3 -m unittest discover -s /tests -p 'test_*.py' -v

# приёмочные: разворачивают оба сервиса и проверяют, что трафик реально идёт
PANEL_IMAGE=noisefloor-panel:dev RELAY_IMAGE=noisefloor-relay:dev tests/smoke.sh
```

Приёмочный тест намеренно считает успехом не «сервис ответил 200», а «через
сервис прошли данные» — до настоящего REALITY-рукопожатия включительно. Это не
педантизм: обе крупные аварии проекта выглядели как совершенно здоровый сервис
с нулевым трафиком, и ровно такая проверка ловит их за минуту.

## Рабочий процесс

**Ветки.** `master` — то, что развёрнуто. Работа идёт в ветках с префиксом:
`feat/`, `fix/`, `docs/`, `refactor/`, `chore/`.

**Коммиты.** Заголовок в повелительном наклонении, до 72 символов, дальше
пустая строка и объяснение **почему**, а не что. Диff показывает, что
изменилось; коммит должен рассказывать, из какой проблемы это выросло.

**Pull request.** Перед отправкой:

- [ ] юнит-тесты зелёные;
- [ ] `tests/smoke.sh` зелёный, если трогали сеть, правила, каскад или сборку;
- [ ] новое поведение закрыто тестом — особенно если чинили баг: сначала тест,
      который падает, потом исправление;
- [ ] документация обновлена, если изменились настройки или порядок установки;
- [ ] `.env.example` обновлён, если появились или исчезли переменные;
- [ ] в коммиты не попали боевые значения — UUID, ключи, адреса серверов;
      для примеров есть документационные диапазоны (`203.0.113.0/24`).

**Проверки.** Автоматического CI пока нет — тесты и сборка гоняются руками
перед публикацией образа (`docker build`, юнит-тесты в собранном образе,
`tests/smoke.sh`, если трогали сеть или каскад). Настроить GitHub Actions —
отдельная задача из списка в конце.

**Релизы.** Образы публикуются с тегом-датой вида `2026-09-10-split-ru` и с
`latest`; тег-дата служит точкой отката. Версии сторонних компонентов (xray,
amneziawg-go, amneziawg-tools, база geoip) закреплены в `Dockerfile` и
меняются отдельным осознанным коммитом — никогда не «подтягиваются сами».

## Принципы

**Версии закреплены.** Ни один компонент не обновляется сам. Раньше сервер раз
в сутки скачивал свежий тег VPN-движка, собирал его прямо в бою и передёргивал
сетевой интерфейс — то есть устраивал обрыв связи в случайное время суток.
Теперь обновление — это `docker compose pull`, запущенный человеком.

**Здоровье измеряется трафиком, а не наличием процесса.** Панель сама делает
пробный запрос через каскад и показывает результат. Запущенный процесс, через
который не проходит ни байта, — это состояние, в котором проект однажды провёл
месяц, не заметив.

**Неправильное состояние должно быть непредставимо.** Правила фаервола живут в
отдельных цепочках, которые очищаются перед заполнением, поэтому сколько раз ни
перезапускай контейнер — останется ровно один комплект. До этого на боевом
сервере успело накопиться семь.

**Ключи не теряются.** Резервные копии снимаются сами, с шифрованием, если
задан пароль.

## Состояние проекта

Работает в бою. Честный список того, что ещё не закрыто, — чтобы не было
сюрпризов:

- **Фаервол не настраивается автоматически.** Панель по умолчанию доступна из
  интернета и работает по HTTP без шифрования. Как закрыть — в
  [`docs/DEPLOY.md`](docs/DEPLOY.md). Автоматизация — следующая задача.
- **Резервные копии лежат на том же сервере.** От случайного удаления спасают,
  от потери сервера — нет. Увозите копию сами.
- **Смена пароля только через `.env`** — кнопки в интерфейсе пока нет.
- **Вход блокируется по имени пользователя**, а не по адресу: пять неверных
  паролей закрывают вход на пять минут, в том числе вам.
- **IPv6 доведён наполовину**: клиентам раздаётся маршрут, выхода нет.
- **У разделения маршрутов нет таблицы исключений.** Российский сайт, который
  не пускает адрес вашего сервера (так ведут себя некоторые госсервисы и
  банки с хостинговыми диапазонами), при включённом разделении не откроется —
  лечится только выключением галочки. Автоматический откат такого адреса в
  каскад — следующий этап.
- **QUIC режется всем подряд.** В режиме `redirect` запрет UDP/443 не смотрит
  на адрес назначения, хотя российским адресам QUIC можно было бы разрешить.
- **Автоматических проверок нет** — ни CI, ни публикации образов по тегу.

## Лицензия

Лицензия не выбрана — по умолчанию это означает «все права защищены».
Репозиторий при этом публичный: код виден всем, но формально использовать его
никто не вправе. Если это не то, чего вы хотите, лицензию нужно добавить явно.
